{# The owner's controls, folded into the one object that is already on every page. Rendered only for a signed-in admin; anonymous HTML contains none of it. It replaces `.admin-bar`, which was fixed at the bottom centre (ADR-027). The bar floated over the end of the document, so every signed-in page had to reserve clearance for it in two properties, and «Выйти» — the rarest action the owner takes — held the most valuable position on the screen. Here nothing covers the page and «Выйти» takes a deliberate second action. The panel is `hidden` in the markup rather than closed by script, so a slow load cannot flash it open. `nav.js` owns the rest: the click, Escape, the click outside, and returning the caret to the button that opened it. #}

{# The mode switch (ADR-028). Two named states, not one toggle sitting on top of hover: «Просмотр» is the page a visitor gets, «Правка» shows every affordance at once. Both halves are here so the mode is legible without reading a pressed state off a single button — the pressed one *is* the indicator F61 asks for. `aria-pressed` starts on «Просмотр» and `edits.js` corrects both halves on load from the same storage the pre-paint script reads — the server cannot know, and these buttons do not exist yet when that script runs. The class itself *is* applied pre-paint, so nothing flashes; what lags is the accessible state, for as long as a deferred script takes. Every later path re-reads the page rather than a variable, which is the part F-019 got wrong. #}
